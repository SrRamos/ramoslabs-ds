# SJIcon and the common icon set: design and task plan

Status: revision 1 after audit (`AUDIT-ICONS`, G-ICON, CONDITIONAL, 2026-10-28; every MUST, SHOULD and NICE finding is applied below). The owner approved the data-prop API. ADR-016 now lives in ARCHITECTURE.md. Not implemented. Base: `main` at cebc999.

Pre-stub commits on this branch (done; they unblock `.a` and `.g`): schema v1 `actions.minItems: 0` plus the semantic rule "no actions requires `events: []`" with a seeded failure and a dated sentence in ADR-010 (MUST-1); `specs:check` `OPTIONAL_DIRS = ['composition']` with a template `.gitkeep` and a seeded failure (MUST-2); `useOptionalRuntime` (React) and `useOptionalSJRuntime` (Vue), which never warn (SHOULD-2); evidence file `at-support/img-role.json` plus `.md`, an INDEX row and the ADR-015 thirteenth-pattern sentence; the clean-room note `evidence/clean-room/icon-prior-inhouse-component.md` (MUST-3).
Sources read: PLAN-WAVE-1.md (section 0, 6.1, 6.2, 9), ARCHITECTURE.md ADR-001/002/003/004/008/009/010/011/013/015, `packages/contracts/contracts/button.contract.json` (golden, `beta`), `docs/implementation/C01-NOTES.md`, `packages/tokens/src/tokens/*`, `packages/css/src/button.css`, `packages/testing/lint/contract/source.js`. The owner's prior in-house icon component was read only for four system properties (currentColor, three sizes 14/20/24 px, kebab-case names mostly matching Feather, always `aria-hidden`) and for the shape of its lazy per-icon load, which is rejected. No glyph or SVG from it is used or copied, and no prior-brand name appears in this repository (BRIEF constraint 1); see the clean-room note.

Glyph source verified: `lucide-static@1.63.0` (ISC, last published 2026-10-28). All 78 icons below exist in it as canonical entries of its `icon-nodes.json` (structured `[tag, attrs]` data; no SVG parsing needed). Measured on that data: a one-icon JS module is 142 B gzip on average and 244 B at the worst of the 78 (`star`); the whole set is about 11.8 KiB gzip if every icon is imported, which no consumer does.

## 1. Decisions

| # | Question | Decision | Why (ADR) |
|---|---|---|---|
| 1 | Placement | **New data package `@ramoslabs/icons`** (no dependencies, no framework, no DOM). The behaviour is a small `icon` module in `@ramoslabs/core` plus `SJIcon` in the three adapters. Adapters and core never depend on or import `@ramoslabs/icons`; consumers import icon data and pass it in. Enforced by boundary rule `sj-boundaries/no-icons-import` plus a manifest test (row .g). | ADR-002 option B (one package per role, dependency direction by lint). Icon data is not behaviour: 78 glyphs inside core would break "core has zero data weight" and its 3 KiB primitive ceiling (ADR-011) and tie the glyph cadence (Lucide bumps) to the kernel. A sprite in `@ramoslabs/css` breaks "no JS" and needs external `<use>` references and ids (SSR and CORS problems). Three copies in the adapters would drift. Because adapters only receive data, there is no coupling, and a team can pass its own icons. |
| 2 | Export shape | **One ESM module per icon, plus a generated barrel and a wildcard subpath.** `import { Search } from '@ramoslabs/icons'` or `from '@ramoslabs/icons/search'`. PascalCase export names (`ChevronRight`) with a generated `<Name>Icon` twin (`ChevronRightIcon`, zero bytes when unused), because `Image`, `Link`, `List`, `Menu` and `Settings` shadow DOM globals and router components; the twin is the recommended import in SFCs and JSX. Kebab-case file and `name` (`chevron-right`). `sideEffects: false`. No registry at module scope, no lazy import in `SJIcon`. | ADR-002 (one ESM entry per unit, a CI proof that the barrel pulls nothing unrelated), ADR-011 (0 KiB for an unused icon, tested with a fixture). Lazy per-icon loading (what `prior icon component` does with a dynamic `import()` per name) is rejected for the component: it renders empty on the server and fills in later, so hydration, layout shift and the accessible name all go wrong (ADR-003 SSR determinism), and the runtime state would be module-scope mutable. Static imports tree-shake and render the same bytes on server and client. |
| 3 | Name lookup (migration path) | `@ramoslabs/icons/by-name` exports the pure function `getIcon(name)` over the **whole** set plus the legacy-alias table. It is not tree-shakeable and says so (size row reported, not gated; measured about 3.4 KiB gzip as one module on lucide-static 1.63.0, and `.g` records the real figure). `SJIcon` itself takes only `icon`. The vanilla `<sj-icon icon="search">` element (the attribute carries a name, the `.icon` property carries data) resolves names through `defineSJIcon({ icons })`, a closure built at the explicit `define()` call. | A `prior icon component name="x"` user migrates by one wrapper line: `<SJIcon :icon="getIcon(name)" />`. Names stay Lucide/Feather-like; renamed ones resolve through the alias table (`alert-circle`, `x-circle`, `more-horizontal`, `home`, `trash-2`, `loader-2`, `filter`, `help-circle`, `circle-help`, `user-circle`). A dev warning names the canonical form. Every alias in `icons.list.json` is validated against Lucide's own re-export table of the pinned package, so an alias can never point at a different glyph (`check-circle` and `edit-2` map upstream to `circle-check-big` and `pen`, not to `circle-check` and `pencil`; those two are outside the 78 and are therefore not offered). ADR-002 explicit `define()`, no import-time registration. |
| 4 | Render form | One inline `<svg viewBox="0 0 24 24">`, children from the icon data, `fill="none" stroke="currentColor" stroke-linecap="round" stroke-linejoin="round"` on the root. `stroke-width` comes from the CSS token. The root also carries `width="1em" height="1em"` as a markup fallback (scales with text, no raw px), because an `<svg>` with only a `viewBox` fills its container before the stylesheet applies; `icon.css` overrides it with the size tokens (`fit`: 100%). No `<use>`, no `<defs>`, no gradients, no `<title>`, no ids. | `currentColor` inherits text colour, so one icon works in every tone and in dark mode. No ids means no IDREF collisions and nothing for the ADR-003 SSR graph check to compare. `<title>` is rejected because AT and tooltips treat it unevenly; the name comes from `aria-label` (below). The presentation attributes and the `1em` box keep a CSS-less render visible and correctly sized. |
| 5 | Stroke width | New token `--icon-stroke-width` (number, value 2, Lucide's grid weight). CSS: `stroke-width: var(--sj-icon-stroke, var(--icon-stroke-width))`. | ADR-009 token-only. The `--sj-icon-stroke` hook lets a theme thin the stroke without forking CSS. Not scaled per size by default (a thinner 14 px stroke looks weak; revisit with a visual review). |
| 6 | Sizes | New tokens `--icon-size-sm` 0.875rem (14 px), `--icon-size-md` 1.25rem (20 px), `--icon-size-lg` 1.5rem (24 px). Prop `size: 'sm' \| 'md' \| 'lg' \| 'fit'`, default `md`, exposed as `data-size`. `fit` = 100% of the parent box. | ADR-009 and AGENTS.md hard rule. The values match the three sizes the owner wants kept (14/20/24). `fit` exists so a button's icon box (`.sj-button__icon`, 1.25em, scales with the button font size) can size the glyph without a cross-component CSS selector. |
| 7 | A11y | **Decorative by default.** No `label`: `aria-hidden="true"`, no `role`, not focusable. With `label`: `role="img"` and `aria-label`, no `aria-hidden`. `label=""` or whitespace is treated as no label and warns in dev. An icon is never interactive and never focusable: `tabindex` is a protected key (deleted with a dev warning, so a spread cannot create an `aria-hidden-focus` violation), and an `on*` handler passed to it also warns in dev (the fix is `SJButton`). | WCAG 1.1.1 and 4.1.2; ADR-004 (library ARIA wins, a spread cannot override `role` or `aria-*`). Meaning is never carried by colour alone (AGENTS.md): a status icon needs `label` or adjacent text. |

A dev warning in the SJIcon getter cannot see its parent, so a source lint rule `contract/icon-label-in-button` is a follow-up (row .f lists it as optional). | ADR-010 (lint semantics unchanged), C01 notes. | 11 | RTL | Each icon in the data has an optional `mirror: true` (set only for glyphs whose direction means "forward/back": `chevron-left`, `chevron-right`, `arrow-left`, `arrow-right`, `log-in`, `log-out`, `undo-2`, `redo-2`, `send`). ### Options considered (short)

- **Registry plus lazy import by name** (the `prior icon component` shape): best for dynamic names, wrong for SSR and tree-shaking, needs module-scope mutable state. Kept only as the opt-in `by-name` helper (decision 3).
- **SVG sprite**: needs `<use href>` to an external file (CORS, SSR, cache), ids, and CSS can't reach into it; rejected.
- **Font icons**: no per-icon tree-shaking, fails with remote-font rules and forced colours; rejected.
- **Icons inside core or each adapter**: rejected (decision 1).
- **Data-only `icon` prop vs. `name` prop**: data prop chosen; `name` is the migration helper.

### Interaction with the contract

`SJIcon` is one flat component with no state machine: contract anatomy `root` (`svg`). Schema v1 now allows `actions: []` (G-ICON ruling), so no fake self-transition is needed; `events: []` is required with it, and there is no `$comment` (the schema forbids extra fields). `pattern.apg` and `pattern.evidence` are both `"img-role"` (one slug, one file; it is WAI-ARIA role `img`, not an APG pattern, and the evidence file says so). The reasons for `support: []` and for having no `variant`/`tone` go in `docs/implementation/C12-NOTES.md` and in the `props[].description` of `icon`. Props: `icon` (`IconData`), `size`, `label`, `dir` (`'ltr' | 'rtl'`, optional override). `runtime: ["dir"]`. `slots: []`. `events: []`. `state.machine: ["idle"]`, `controllable: []`, `actions: []`, `focus.strategy: "native"` with no owner. `status: draft`, to `beta` when the getters freeze. Fixtures: `default`, `sizes`, `labelled`, `rtl-mirror`, `unknown-node`. `a11y.wcag`: `1.1.1`, `1.4.11`, `4.1.2`. `atAssertions`: `manual-icon-decorative-skipped`, `manual-icon-label-announced`. `atSupport` follows the ADR-015 policy (VoiceOver real-test pending, others `evidence-only` from the registry).

**Evidence.** `at-support/img-role.json` is in the registry (13 files validate; entries omit `focusStrategy` in `constraints`, so W1-317's conflict check has nothing to compare). The `.a` dependency on it is met.

### Color contrast

`SJIcon` has no `variant`/`tone`: colour is inherited from the parent. A meaningful (labelled) icon is a graphical object under WCAG 1.4.11 (3:1). That is guaranteed where the parent is a library component already in the W1-203 matrix (e.g. SJButton). For standalone use the docs state the rule and the L3 composition spec checks 3:1 for the documented usage recipes. A `tone` axis is a possible later addition, not in scope.
