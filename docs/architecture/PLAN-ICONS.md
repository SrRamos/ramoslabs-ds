# SJIcon and the common icon set: design and task plan

Status: design for audit. Not implemented. Author: design pass, 2026-10-28. Base: `main` at cebc999.
Sources read: PLAN-WAVE-1.md (section 0, 6.1, 6.2, 9), ARCHITECTURE.md ADR-001/002/003/004/008/009/010/011/013/015, `packages/contracts/contracts/button.contract.json` (golden, `beta`), `docs/implementation/C01-NOTES.md`, `packages/tokens/src/tokens/*`, `packages/css/src/button.css`, `packages/testing/lint/contract/source.js`. The quext-core `QxtIcon` files were read only for system design (currentColor, three sizes 14/20/24 px, kebab-case names, lazy per-icon load, always `aria-hidden`). No glyph or SVG from quext-core is used or copied.

Glyph source verified: `lucide-static@1.63.0` (ISC, last published 2026-10-28). All 78 icons below exist in it as canonical entries of its `icon-nodes.json` (structured `[tag, attrs]` data; no SVG parsing needed). Measured on that data: a one-icon JS module is 142 B gzip on average and 244 B at the worst of the 78 (`star`); the whole set is about 11.8 KiB gzip if every icon is imported, which no consumer does.

## 1. Decisions

| # | Question | Decision | Why (ADR) |
|---|---|---|---|
| 1 | Placement | **New data package `@ramoslabs/icons`** (no dependencies, no framework, no DOM). The behaviour is a small `icon` module in `@ramoslabs/core` plus `SJIcon` in the three adapters. Adapters do not depend on `@ramoslabs/icons`; consumers import icon data and pass it in. | ADR-002 option B (one package per role, dependency direction by lint). Icon data is not behaviour: 78 glyphs inside core would break "core has zero data weight" and its 3 KiB primitive ceiling (ADR-011) and tie the glyph cadence (Lucide bumps) to the kernel. A sprite in `@ramoslabs/css` breaks "no JS" and needs external `<use>` references and ids (SSR and CORS problems). Three copies in the adapters would drift. Because adapters only receive data, there is no coupling, and a team can pass its own icons. |
| 2 | Export shape | **One ESM module per icon, plus a generated barrel and a wildcard subpath.** `import { Search } from '@ramoslabs/icons'` or `from '@ramoslabs/icons/search'`. PascalCase export names (`ChevronRight`), kebab-case file and `name` (`chevron-right`). `sideEffects: false`. No registry at module scope, no lazy import in `SJIcon`. | ADR-002 (one ESM entry per unit, a CI proof that the barrel pulls nothing unrelated), ADR-011 (0 KiB for an unused icon, tested with a fixture). Lazy per-icon loading (what `QxtIcon` does with a dynamic `import()` per name) is rejected for the component: it renders empty on the server and fills in later, so hydration, layout shift and the accessible name all go wrong (ADR-003 SSR determinism), and the runtime state would be module-scope mutable. Static imports tree-shake and render the same bytes on server and client. |
| 3 | Name lookup (migration path) | `@ramoslabs/icons/by-name` exports the pure function `getIcon(name)` over the **whole** set plus the legacy-alias table. It is not tree-shakeable and says so (size row reported, about 12 KiB gzip). `SJIcon` itself takes only `icon`. The vanilla `<sj-icon name="search">` element resolves names through `defineSJIcon({ icons })`, a closure built at the explicit `define()` call. | A `QxtIcon name="x"` user migrates by one wrapper line: `<SJIcon :icon="getIcon(name)" />`. Names stay Lucide/Feather-like; renamed ones resolve through the alias table (`alert-circle`, `check-circle`, `x-circle`, `more-horizontal`, `home`, `edit-2`, `trash-2`, `loader-2`, `filter`). A dev warning names the canonical form. ADR-002 explicit `define()`, no import-time registration. |
| 4 | Render form | One inline `<svg viewBox="0 0 24 24">`, children from the icon data, `fill="none" stroke="currentColor" stroke-linecap="round" stroke-linejoin="round"` on the root. `stroke-width`, `width` and `height` come from CSS tokens, never attributes. No `<use>`, no `<defs>`, no gradients, no `<title>`, no ids. | `currentColor` inherits text colour, so one icon works in every tone and in dark mode. No ids means no IDREF collisions and nothing for the ADR-003 SSR graph check to compare. `<title>` is rejected because AT and tooltips treat it unevenly; the name comes from `aria-label` (below). The presentation attributes on the root keep a CSS-less render visible. |
| 5 | Stroke width | New token `--icon-stroke-width` (number, value 2, Lucide's grid weight). CSS: `stroke-width: var(--sj-icon-stroke, var(--icon-stroke-width))`. | ADR-009 token-only. The `--sj-icon-stroke` hook lets a theme thin the stroke without forking CSS. Not scaled per size by default (a thinner 14 px stroke looks weak; revisit with a visual review). |
| 6 | Sizes | New tokens `--icon-size-sm` 0.875rem (14 px), `--icon-size-md` 1.25rem (20 px), `--icon-size-lg` 1.5rem (24 px). Prop `size: 'sm' \| 'md' \| 'lg' \| 'fit'`, default `md`, exposed as `data-size`. `fit` = 100% of the parent box. | ADR-009 and AGENTS.md hard rule. The values match the three sizes the owner wants kept (14/20/24). `fit` exists so a button's icon box (`.sj-button__icon`, 1.25em, scales with the button font size) can size the glyph without a cross-component CSS selector. |
| 7 | A11y | **Decorative by default.** No `label`: `aria-hidden="true"`, no `role`, not focusable. With `label`: `role="img"` and `aria-label`, no `aria-hidden`. `label=""` or whitespace is treated as no label and warns in dev. An icon is never interactive and never focusable: interactive use goes inside `SJButton`. | WCAG 1.1.1 and 4.1.2; ADR-004 (library ARIA wins, a spread cannot override `role` or `aria-*`). Meaning is never carried by colour alone (AGENTS.md): a status icon needs `label` or adjacent text. |
| 8 | Icon-only button | **No change to `SJButton`.** An icon-only button keeps its accessible name from the button's own `label` (lint `contract/icon-only-name` already counts only `label`/`aria-label`/`aria-labelledby`, never visible content, so an `SJIcon` child cannot satisfy it and must not). The icon in the button's `icon` slot stays decorative; the button's `icon` part already sets `aria-hidden="true"`, so an `SJIcon label` placed there would be hidden. A dev warning in the SJIcon getter cannot see its parent, so a source lint rule `contract/icon-label-in-button` is a follow-up (row .f lists it as optional). | ADR-010 (lint semantics unchanged), C01 notes. The button is `beta`: contract and getters are frozen, so SJButton gets nothing new. |
| 9 | SJButton consumption | Existing `icon` slot, unchanged contract: `<SJButton><template #icon><SJIcon :icon="Plus" size="fit" /></template>Add</SJButton>`. Needs no edit to `button.css`, `button.contract.json`, or core getters. The conformance proof (button with an SJIcon, icon-only with SJIcon, `link` variant) lives in `testing/specs/icon/composition/`, not in the button spec. | ADR-010 `beta` (frozen; only fixtures, parity and visual lanes move). It also closes the C01 follow-up that vanilla `icon-only` renders a non-text glyph and leaves axe `incomplete` items (C01-NOTES, "axe incomplete for icon-only"): the real SVG has no text to contrast-check. |
| 10 | Forced colors | Stroke is `currentColor`, which the UA maps to `CanvasText`/`ButtonText`. The CSS sets no `forced-color-adjust: none`, no `fill`/`stroke` colours, no `filter`. A fixture runs under `forced-colors: active` emulation and asserts the stroke resolves to a system colour and stays visible on `Canvas`. | ADR-009 and plan W1-204 (forced-colors fixture). No extra CSS bytes. |
| 11 | RTL | Each icon in the data has an optional `mirror: true` (set only for glyphs whose direction means "forward/back": `chevron-left`, `chevron-right`, `arrow-left`, `arrow-right`, `log-in`, `log-out`, `undo-2`, `redo-2`, `send`). The core getter emits `data-mirror="true"` when `icon.mirror` and the resolved `dir` is `rtl`; CSS: `.sj-icon[data-mirror] { transform: scaleX(-1); }`. `dir` comes from the explicit `dir` prop, else `runtime.dir`. | ADR-009 (RTL default), ADR-003 (`dir` is runtime state, never read from `document`). Not `:dir(rtl)`: it needs Chromium 120 and the floor is 114 (ADR-001). Symmetric and non-directional glyphs (`external-link`, `arrow-up-right`, `arrow-left-right`, `message-square`) are not mirrored. |
| 12 | SSR | Pure function of props. Identical markup on server and client, no ids, no effects, no store, no timers. | ADR-003, ADR-013 SSR runner (`testing/ssr`). |
| 13 | Safety | Icon nodes are rendered by element creation, never `innerHTML`; the core accepts only an allowlist of SVG tags (`path circle ellipse rect line polyline polygon`) and attributes (geometry attributes only; no `on*`, `href`, `style`, `class`, `id`). Anything else is dropped with a dev warning. Applies to consumer-supplied icons. | ADR-002 text-safety rule (text nodes / created elements only, tested in ADR-013 layer 2). |
| 14 | Byte ceilings | Per icon module: **0.4 KiB gzip** (minified, tree-shaken, ADR-011 method). A listed exception file may allow up to **0.75 KiB** for a named icon with a reviewed reason (none expected: the largest of the 78 measures 0.24 KiB). `SJIcon` core (`core/src/icon`): **0.75 KiB** gzip (a simple primitive is capped at 3 KiB; icon is a pure attribute function plus an allowlist). One-icon fixture: SJIcon core + one icon, **no shared kernel**, so about 1 KiB gzip total; the Vue/React/vanilla adapter rows are reported separately (ADR-011). Unused icon in a fixture importing another: **0 KiB**. Full set (barrel import everything, `by-name`): reported, not gated. | ADR-011 (provisional, revisable only by ADR; first measurement in .g/.a cites real numbers, no ceiling moves above +50% without design review). |
| 15 | Licence | `lucide-static` is a **pinned devDependency** (exact version, no range) of `@ramoslabs/icons`, fetched only at codegen. Generated per-icon modules are **committed** and a `--check` mode fails CI on drift. The package ships `LICENSE` (MIT, ours) and `THIRD-PARTY-NOTICES.md` with Lucide's ISC text and Feather's MIT notice (taken verbatim from the pinned `lucide-static/LICENSE`, regenerated by the same script), and every generated module carries an `// ISC, Lucide Contributors` header comment. `files` includes the notice; a dist scan fails if it is missing. | Repo rule: zero runtime dependencies (ADR-002 table). Committed output keeps builds offline and makes each Lucide bump a reviewable path-data diff. |

### Options considered (short)

- **Registry plus lazy import by name** (the `QxtIcon` shape): best for dynamic names, wrong for SSR and tree-shaking, needs module-scope mutable state. Kept only as the opt-in `by-name` helper (decision 3).
- **SVG sprite**: needs `<use href>` to an external file (CORS, SSR, cache), ids, and CSS can't reach into it; rejected.
- **Font icons**: no per-icon tree-shaking, fails with remote-font rules and forced colours; rejected.
- **Icons inside core or each adapter**: rejected (decision 1).
- **Data-only `icon` prop vs. `name` prop**: data prop chosen; `name` is the migration helper.

### Interaction with the contract

`SJIcon` is one flat component with no state machine: contract anatomy `root` (`svg`). Props: `icon` (`IconData`), `size`, `label`, `dir` (`'ltr' | 'rtl'`, optional override). `runtime: ["dir"]`. `slots: []`. `events: []`. `state.machine: ["idle"]`, `controllable: []`. `status: draft`, to `beta` when the getters freeze. Fixtures: `default`, `sizes`, `labelled`, `rtl-mirror`, `unknown-node`. `a11y.wcag`: `1.1.1`, `1.4.11`, `4.1.2`. `atAssertions`: `manual-icon-decorative-skipped`, `manual-icon-label-announced`. `atSupport` follows the ADR-015 policy (VoiceOver real-test pending, others `evidence-only` from the registry).

**Evidence dependency (not an owner question).** `pattern.evidence` is required (G2 ruling) and must resolve in `docs/architecture/evidence/at-support/`. There is no `img`/decorative-SVG file there today (existing: button, checkbox, dialog-modal, disclosure, live-region, popover-nonmodal, radio-group, select-only-combobox, switch, tabs, ...). The research peer needs to add `img-role.json` (role `img` with `aria-label`, and `aria-hidden` decorative) before W1-C12.a can pass W1-317. Until then the contract cannot validate.

### Color contrast

`SJIcon` has no `variant`/`tone`: colour is inherited from the parent. A meaningful (labelled) icon is a graphical object under WCAG 1.4.11 (3:1). That is guaranteed where the parent is a library component already in the W1-203 matrix (e.g. SJButton). For standalone use the docs state the rule and the L3 composition spec checks 3:1 for the documented usage recipes. A `tone` axis is a possible later addition, not in scope.

## 3. Draft ADR-016 (append to ARCHITECTURE.md after audit)

### ADR-016: Icon package and SJIcon

**Context.** Components need glyphs (the SJButton `icon` slot exists and is `beta`) and consumers migrating from a prior system expect a name-based, `currentColor`, three-size icon with kebab-case names. The rules in force: zero runtime dependencies (ADR-002), core carries no data weight and no DOM (ADR-002, ADR-011), token-only styling (ADR-009), SSR determinism with no ids (ADR-003), text/created elements only, never `innerHTML` (ADR-002), contracts are frozen at `beta` (ADR-010). A glyph source with a permissive licence is needed (owner decision: Lucide, ISC).

**Options considered.**
A. Icons inside `@ramoslabs/core` or each adapter.
B. New data package `@ramoslabs/icons` plus `SJIcon` taking icon data as a prop (no adapter dependency on the package).
C. Name-based component with a lazy registry (dynamic `import()` per name).
D. SVG sprite or icon font.

**Decision.** Option B.
- `@ramoslabs/icons`: one ESM module per icon (`{ name, nodes, mirror? }`, `nodes` is Lucide's `[tag, attrs]` structure), generated and committed from a pinned `lucide-static` devDependency; generated barrel, `./*` subpath, `./by-name` pure helper with the legacy-alias table. Zero dependencies. `LICENSE` plus `THIRD-PARTY-NOTICES.md` (ISC, Feather MIT) ship in `files`.
- `@ramoslabs/core/icon`: pure getters for the `root` part and a sanitized node list (tag and attribute allowlist). `SJIcon` in Vue, React and vanilla renders `<svg viewBox="0 0 24 24">` with `currentColor`.
- Decorative by default (`aria-hidden`); `label` gives `role="img"` and `aria-label`. Never focusable.
- Tokens `icon.size.{sm,md,lg}` (14/20/24 px), `icon.stroke.width` (2). Sizes `sm|md|lg|fit`.
- RTL: `mirror` flag in the data, applied from `dir` with `scaleX(-1)`; no `:dir()` (floor).
- Ceilings (ADR-011, provisional): 0.4 KiB gzip per icon (0.75 exception), 0.75 KiB core `icon`, 0 KiB unused icon.
- The package version moves in lockstep with the others (changesets, ADR-002).

**Consequences.** One more published package and one codegen script. Lucide bumps are reviewable diffs of path data and may rename icons (aliases keep names stable; a renamed canonical name is a breaking change handled by the alias table plus a changeset note). Consumers write one import per icon; dynamic-name use goes through the non-tree-shakeable helper and says so. SJButton is untouched. Amends ADR-002's table (one row, runtime deps none), ADR-009 (three icon-size tokens, one stroke token), ADR-011 (icon rows).

**Sources.** ADR-002, 003, 004, 009, 010, 011; C01-NOTES; Lucide licence (ISC) at the pinned version.

## 5. Risks and follow-ups

- **Lucide renames.** Upstream moves canonical names (it has already turned `trash-2` into an alias of `trash`, `home` into `house`). Mitigation: the pinned version, the generated-diff review, the alias table.

## 6. Question for the owner

None blocks the design. One preference to confirm: the data-prop API (`<SJIcon :icon="Search" />`) with `by-name` only as an explicit migration helper, rather than a name-string `SJIcon` backed by a registry. This design assumes the former because the latter cannot be SSR-deterministic and tree-shakeable at once.
