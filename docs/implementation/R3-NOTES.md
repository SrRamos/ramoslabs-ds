# R3 notes: vanilla runtime (W1-122)

Branch `feature/m1-r3-vanilla-runtime`. Code: `packages/vanilla/src/runtime/index.ts`. Spec: ADR-003 bridge row (vanilla), ADR-002, ADR-014.

## Design
- `createHost(runtime, { idFactory?, liveHost? })` returns `{ mount(el, spec, props), live, destroy }`. One host per runtime holds the single
  live-region registry (W1-111); no module-scope state (a module WeakMap was ruled out in K1b). The row's `mount(el, runtime)` is this host
  method: the runtime is bound once at `createHost`, because the live registry must be per runtime.
- `ComponentSpec { initial, reduce, fields, patch, attach, run, exists }` is what W1-120/121/12x.e components supply. Per instance: store,
  K1b `createControlled`, K1 effect queue, one `AbortController`.
- Order in `mount`: patch (first) -> `controlled.mount()` -> store subscribe -> `attach` -> schedule a drain.
- Patches are synchronous on store change and `update(props)`; effects drain in a `runtime.scheduler.soon` microtask: `reconcile()` descriptors
  are enqueued (stamped with the latest store version, so a newer reducer effect of the same type/target supersedes them), then layout, then
  passive phase. Effects enqueued during a drain trigger another microtask.
- `ctx.dispatch` throws in development when called from `run` (ADR-003 "no synchronous re-dispatch"). `update` calls `controlled.view()` so an
  ownership switch throws to the caller, not inside the microtask.
- `ctx.listen` always adds `{ signal }`; `destroy` aborts, unsubscribes, destroys the store, clears the queue, runs `onCleanup`s newest first.
  Idempotent; pending microtasks and later events are no-ops.
- Ids: `baseId(props.id, acquire, runtime.idPrefix)`; `acquire` = `options.idFactory ?? runtime.idFactory`, else a clear throw (ADR-003: vanilla needs
  an injected factory or explicit ids). W1-114 relies on the injected one.
- Text only: `setText` uses `textContent`. No `innerHTML`, no `attachShadow` anywhere in the runtime (light DOM, ADR-002).
- Default live host appends `div[role][aria-live][aria-atomic].sj-sr-only` to `ownerDocument.body` on first mount (client only, after mount).

## Shared-file change (outside `runtime/**`)
- `packages/vanilla/package.json`: added `dependencies: { "@ramoslabs/core": "workspace:*" }` (the runtime imports core subpaths; turbo builds core first).
  `bun.lock` regenerated by `bun install`.

## Follow-ups
- css stream: define the `sj-sr-only` visually-hidden class (live nodes use it; no styles hardcoded here).
- Tests run in node with a recording `EventTarget` double (no jsdom in the repo); real-DOM L2 coverage belongs with the component rows.
- Retention: 1,000 cycles leave 0 live listeners and 0 pending scheduler work; a WeakRef/gc check confirms state objects are collectable.
