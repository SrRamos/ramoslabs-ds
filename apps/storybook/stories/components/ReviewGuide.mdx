# Component review guide

Try every component by hand. Each story’s description says what to press and what a screen reader should say. Do each check in **Chromium**, then repeat the keyboard ones in Firefox and Safari if you can. Turn on a screen reader (VoiceOver: Cmd+F5) for the announcement checks.

**Every component, every time**

- **Tab** reaches it (unless disabled) and a clear focus ring shows.
- Works with keyboard alone; the mouse is optional.
- Look is styled and readable in light and in dark (toolbar Theme); state is never shown by colour alone.
- The **RTL** story mirrors correctly.
- Zoom to 200%: nothing is clipped or overlaps.

## Not available to review

Dialog, Popover, Radio Group, Select, Tabs and Tooltip are placeholders in `@ramoslabs/vue` (an empty module), so they have no stories yet. Add them when each ships.

## Known limits (from the C-notes)

- **Two announcements at once**: when two fields or states announce in the same moment, only the last text is spoken. Both stay visible. (C02, C11)
- **Disclosure fallback**: current engines all group `<details name>` natively, so the owned fallback is covered by unit tests only, not by what you see here. (C06)
- **Safari floor**: `details name` is native from Safari 17.2; the contract records 18 as the conservative major (issue #92). `:user-invalid` has a fallback below Chromium 119 / Safari 16.5 that you cannot trigger here.
- **VoiceOver wording** in the disclosure notes ("disclosure triangle", "expanded") is a best guess; what you actually hear is the authority. Report any difference.
- **Playwright AX-tree checks** run in Chromium only (issue #49); other engines are covered by ARIA snapshots.
- **Switch/Checkbox controlled mode**: the owner must accept synchronously inside the change event, otherwise the control snaps back until its render commits.
